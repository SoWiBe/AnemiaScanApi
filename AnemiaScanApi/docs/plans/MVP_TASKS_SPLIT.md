## 2. Карим — UI, контент, сторы

### Контент курсов — самое длинное по времени, начинать первым

| Задача | Комментарий |
|---|---|
| 1–2 курса на 14–21 день | Сейчас в базе **ноль курсов**: движок готов, каталог отдаёт пустой список. Без контента главной ценности приложения («что мне делать») просто нет |
| Структура каждого дня | Теория в Markdown + список задач + флаг «день пересъёмки» (чекпоинт, где пользователя просят снять глаз заново) |
| Чекпоинт-дни | Расставить по курсу — по ним строится график Hb в прогрессе. Разумно: старт, середина, финал |
| Ревью своими силами + ИИ-проверка | Врача на MVP не будет. **Поэтому в текстах не должно быть назначений**: ни препаратов, ни дозировок, ни схем приёма. Только питание, образ жизни и «когда идти к врачу» |
| Аудитории | В модели курса есть `Adult / Pregnant / Child / Postpartum`. На MVP достаточно `Adult`; детская аудитория — вторым курсом, если успеваем |
| Тексты дисклеймера и политики | Формулировки для P0 №12 и №13: «скрининг, не диагноз, не медицинское изделие» + политика конфиденциальности под подпись галкой |

Контент можно набирать в любом удобном виде (док, таблица) — Алексей даёт JSON-схему, конвертация не ваша забота.

### Фронт

| Экран / задача | Зависит от |
|---|---|
| Экран результата скана: вердикт + дисклеймер | Правило единого вердикта (P0 №11, Алексей) |
| **Убрать из клиента всё платёжное** | Уже сделано на бэке: эндпоинтов `/payments/*` больше нет, из `GET /courses` и `GET /courses/{slug}` пропали `isFree`, `priceUsdc`, `priceKzt`, `freeDaysPreview`. Если клиент парсит их как обязательные — сломается |
| История сканов | `GET /analysis/history` (P0 №8, Алексей) |
| Каталог курсов, карточка курса, запись на курс | Готово на бэке |
| Экран «сегодня»: теория, задачи, отметка выполнения | Готово на бэке |
| Стрики и прогресс, график Hb по чекпоинтам | Готово: `.../progress` уже отдаёт таймлайн |

## 3. Совместные решения

### Формат съёмки — единственный открытый вопрос плана

Референсный объект в кадре или калибровка по склере. Почему важно: это и самый большой прирост точности на имеющихся данных, и формат **всех** снимков, которые соберутся после релиза — сменить позже значит обесценить накопленный датасет.

- **Алексей:** прогоняет оба варианта на India + Italy, приносит цифры.
- **Карим:** оценивает, насколько вариант с карточкой реалистичен для пользователя.
- **Решаем по цифрам, не заранее.** Дедлайн — до старта работ по экрану съёмки.

### Что показывать взрослым, пока модель не дообучена

Сейчас взрослым выдаётся Hb по детской шкале. До того, как взрослая часть обучена и измерена, честнее показывать вероятностную оценку без числа Hb. Формулировка — на двоих: Алексей за то, что отдаёт API, Карим за то, как это читается на экране.

### Правило единого вердикта

TF-классификатор и CIELab-регрессия могут противоречить друг другу. Алексей определяет правило согласования, Карим — как оно выглядит на экране результата.

### Контракт API

Любое изменение полей — в обе стороны заранее. Уже поменялось: платёжные поля курсов и эндпоинты `/payments/*` удалены. Впереди: `/analysis/history`, поле согласия при регистрации, формат вердикта.

## 4. Стыки: кто кого блокирует

| Блокирует | Кого | Когда нужно |
|---|---|---|
| JSON-схема курса (Алексей) | Массовый набор контента (Карим) | В первую неделю, иначе контент придётся переделывать |
| Решение по формату съёмки (оба) | Экран съёмки (Карим) и финальное обучение (Алексей) | До конца фазы 2 |
| `GET /analysis/history` (Алексей) | Экран истории (Карим) | Фаза 3 |
| Правило вердикта (Алексей) | Экран результата (Карим) | Фаза 3 |
| Контент курсов (Карим) | Наполнение базы и приёмка на проде (Алексей) | До фазы 4 |
| Тексты дисклеймера и политики (Карим) | P0 №12 и №13 (Алексей) | Фаза 1–2 |
| Аккаунты разработчика (Карим) | Подача в сторы (Алексей) | Оформлять с самого начала |

## 6. Чего не делаем

Монетизация (платёжный слой удалён целиком), Kaspi и Solana, реальные on-chain платежи, админка курсов с UI, дашборды и расширенная аналитика, CNN вместо CIELab, перенос TF-классификатора на ONNX, Docker/Kubernetes, push-уведомления, соцлогины, мультиязычность.

Единственное, что вернулось к обсуждению из-за переезда Mongo в облако — выносить ли снимки в S3/R2 вместо GridFS. Считаем после того, как заработает downscale.
