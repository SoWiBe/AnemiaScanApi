# ADR 002: CIELab-регрессия Hb как дополнительная модель предсказания

## Status
Proposed

## Context
Текущая продовая модель (`LLM/anemia_v10_more_aug.zip`, ML.NET + TensorFlow,
`PredictionService`/`IPredictionService`) — бинарный классификатор всего
изображения (`Low_Hb` / не-`Low_Hb`) с confidence-score. Она не даёт
непрерывное значение Hb: поле `AnemiaScan.HemoglobinLevel` в схеме есть с
самого начала, но всегда записывалось как `null` (см. комментарий «пока не
можем предоставить данную информацию» в старой версии `AnemiaAnalysisService`).

Параллельно в `anemia-machine-learning` (см. `PLAN_pretraining_and_api_integration.md`)
проведён обязательный эксперимент по эффекту утечки дубликатов на датасете
CP-AnemiC и обучена модель регрессии Hb по признакам CIELab конъюнктивы
(`GradientBoostingRegressor` на `L, a, b`):

- Leakage-free оценка (условие C, официальный `StratifiedKFold` по
  квартилям Hb, 394 записи без дублей): MAE=1.518, r=0.387.
- Эффект утечки дубликатов подтверждён отдельно (условие A vs B на 710
  записях: r падает с 0.484 до 0.361 для этой же модели) — оценка 0.387
  выше не завышена утечкой.
- Экспортирована в ONNX (`skl2onnx`), численный паритет с sklearn ~1e-6.
- Feature-экстрактор (CIELab по видимым, `alpha>=250`, пикселям — маска
  ROI, не прямоугольный кроп) перенесён на C# и сверен golden-тестом с
  Python на 22 изображениях — точное совпадение (см.
  `AnemiaScanApi.Tests/ML/`).

**Ограничение** (см. `datacard.json` датасета): независимость участников не
подтверждена — в исходных данных нет идентификатора пациента. Абсолютные
цифры MAE/r не следует представлять как окончательную клиническую точность.

## Decision
Добавить CIELab-регрессию как **отдельный, дополнительный** путь предсказания
(`IHemoglobinPredictionService` / `HemoglobinPredictionService`,
`ML/CielabFeatureExtractor.cs`, `ML/HbOnnxPredictor.cs`), не заменяя
существующий TF-классификатор:

- `AnalysisController` вызывает оба пути на каждый запрос: TF-классификатор
  по-прежнему определяет `Sick`/`Confidence` (без изменений в поведении для
  существующих клиентов); CIELab-регрессия дополнительно заполняет
  `HemoglobinLevel` и `Severity`.
- Если CIELab-путь падает (битое изображение, нет видимых пикселей и т.п.),
  `TryPredictAsync` возвращает `null` вместо исключения — основной анализ
  анемии не должен зависеть от нового, менее проверенного в проде пути.
- `AnemiaScan.ModelVersion` теперь заполняется (`ModelVersions.CielabHemoglobinRegression`,
  `"cielab-gb-v1"`) — раньше объявлялось в схеме, но никогда не
  устанавливалось. Отражает только версию регрессии Hb, не версию TF-модели.
- Пороги severity (`ML/SeverityBands.cs`) — округлённые точки 7/10/11
  г/дл, соответствующие стандартной шкале ВОЗ для детей 6-59 месяцев
  (возрастной диапазон CP-AnemiC — 6-60 месяцев). Это интерпретация
  наблюдаемых в датасете эмпирических границ, а не дословная формула из
  источника — см. комментарий в коде и `SeverityBandsTests`.

## Consequences

### Положительные
- `HemoglobinLevel`/`Severity` в ответе API и в Mongo наконец получают
  реальные значения — годами существовавший, но незаполняемый функционал.
- ONNX Runtime — CPU-инференс без зависимости от TensorFlow-рантайма для
  этого конкретного пути.
- Golden-тесты (`CielabFeatureExtractorTests`, `HbOnnxPredictorTests`,
  `HemoglobinPredictionServiceTests`) защищают от расхождения между
  Python-обучением и C#-инференсом при будущих изменениях любой стороны.

### Отрицательные / риски
- Два независимых предсказания на одно изображение могут разойтись по
  смыслу (например TF говорит `Anemia`, CIELab-регрессия даёт Hb в диапазоне
  Non-Anemic) — контракт ответа это не отрицает и не примиряет, оставлен
  как facts side-by-side до отдельного решения о конфликте.
- Пороги severity — интерпретация, не проверенная напрямую по исходной
  статье CP-AnemiC (см. Decision выше).
- `SixLabors.ImageSharp` лицензируется по Six Labors Split License —
  **проверено 25.09.2026, бесплатный тир применим** (см. «Лицензия
  ImageSharp» ниже). Остаточный риск не юридический, а технический:
  извлечение CIELab завязано на декодер ImageSharp.
- Абсолютная точность модели (MAE~1.5 г/дл) скромная — `not_claimable` из
  `datacard.json` (независимость участников не подтверждена) должен
  сопровождать любое представление этих цифр как клинически точных.

## Alternatives Considered
1. **Сразу заменить TF-классификатор новой моделью** — отклонено: TF-модель
   уже в проде, замена без промежуточного этапа сравнения на реальном
   трафике рискованна для существующих пользователей.
2. **Отдельный HTTP-микросервис на Python для инференса** — отклонено:
   лишняя инфраструктура ради модели, которая укладывается в ONNX + 100
   строк C#; текущий проект и так embed-ит модели в процесс (см. ADR 001
   про гибкость схемы под ML).
3. **Хардкод весов Ridge вместо ONNX** — рассматривался в плане как более
   лёгкий вариант, не выбран, т.к. финальная модель — GradientBoosting
   (превосходит Ridge на leakage-free оценке), а для неё ONNX — практически
   единственный разумный путь переноса дерева решений.

## Лицензия ImageSharp (P0 №15)

Проверено 25.09.2026 по тексту лицензии в репозитории SixLabors/ImageSharp
и странице тарифов. **Это разбор текста лицензии, а не юридическое
заключение.**

`SixLabors.ImageSharp` 3.1.12 подключён прямой зависимостью в
`AnemiaScanApi.csproj`, то есть в терминах лицензии это Direct Package
Dependency («any Work in Source or Object form that is installed directly
by You»).

Условия Apache 2.0 (то есть бесплатно) применяются, если выполнено любое из:

- потребитель — **for-profit с годовой валовой выручкой менее 1M USD**;
- потребитель — НКО или зарегистрированная благотворительная организация;
- библиотека используется в софте под open source / source available лицензией;
- зависимость транзитивная, а не прямая.

Во всех прочих случаях нужна коммерческая лицензия Six Labors.

**Вывод для AnemiaScan:** проект — for-profit, но до-выручечный (платёжный
слой удалён 22.09.2026, курсы бесплатны безусловно), то есть глубоко ниже
порога 1M USD. Бесплатный тир применим, покупать ничего не нужно.
Закрытость исходников роли не играет: в списке условий выше открытость —
альтернативное основание, а не обязательное. Серверное использование текст
лицензии отдельно не оговаривает, триггер — только выручка и характер
зависимости.

**Триггер для пересмотра:** годовая валовая выручка **компании** (не
приложения) достигает 1M USD. Тогда — коммерческая лицензия на весь набор
Six Labors либо миграция.

**Почему миграция дороже, чем кажется.** ImageSharp используется в трёх
местах, и они не равноценны:

| Где | Что делает | Стоимость замены |
|---|---|---|
| `ML/CielabFeatureExtractor` | Декод пикселей для CIELab-признаков | **Высокая.** Признаки должны совпадать с Python-пайплайном 1:1; другой декодер может дать другие значения пикселей и сдвинуть признаки. Любая замена требует повторной сверки golden-фикстур |
| `Infrastructure/Services/HemoglobinPredictionService` | Загрузка изображения | Низкая |
| `Infrastructure/Utils/ImageCompressor` | Downscale + JPEG перед GridFS (P0 №9) | Низкая, тривиально переносится на SkiaSharp или Magick.NET |

То есть если когда-нибудь придётся уходить с ImageSharp, основная работа —
не замена API, а повторная валидация CIELab-экстрактора против
`Fixtures/conjunctiva_golden.json`.
