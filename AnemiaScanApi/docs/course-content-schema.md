# Схема курса: как сдавать контент

> Для автора контента. Один курс — один JSON-файл.
>
> Машинная схема: [`schemas/course.schema.json`](schemas/course.schema.json)
> Готовый пример: [`examples/course-example.json`](examples/course-example.json)

Контент можно набирать в чём угодно — в доке, в таблице, в заметках. Конвертация
в этот формат не ваша забота, но **структуру стоит держать в голове с самого
начала**: если набрать текст без деления на дни и задачи, потом придётся
переразбивать вручную.

---

## Главное правило: без назначений

Клинического ревью на MVP не будет, поэтому в текстах **не должно быть**:

- названий препаратов,
- дозировок,
- схем приёма,
- рекомендаций начать или прекратить приём чего-либо.

Можно и нужно: питание, образ жизни, сон, привычки и **«когда идти к врачу»**.

Это не перестраховка, а граница между «рекомендациями по образу жизни» и
медицинской услугой. Ровно по ней проходит и требование сторов к health-приложениям.

## Структура файла

```jsonc
{
  "slug": "iron-basics-7",          // идентификатор, менять нельзя после публикации
  "title": "Железо в тарелке: 7 дней",
  "description": "Короткое описание для карточки каталога.",
  "targetAudience": "Adult",        // на MVP всегда Adult
  "durationDays": 7,                // = количеству элементов в days
  "contentStatus": "Draft",         // Published — когда готово к показу
  "doctorReviewerName": null,       // на MVP остаётся пустым
  "days": [ /* ... */ ]
}
```

### Поля курса

| Поле | Что это | Обязательно |
|---|---|---|
| `slug` | Идентификатор в URL: строчные латинские буквы, цифры, дефисы. **После публикации не менять** — на него ссылается мобилка | да |
| `title` | Заголовок карточки, до 200 символов | да |
| `description` | Описание для каталога, обычный текст (не Markdown), до 1000 символов | да |
| `targetAudience` | `Adult`, `Pregnant`, `Child` или `Postpartum`. На MVP достаточно `Adult` | да |
| `durationDays` | Длительность в днях. Ориентир для MVP — 14–21 | да |
| `contentStatus` | `Draft` → `DoctorReview` → `Published`. В каталоге видны только `Published` | нет, по умолчанию `Draft` |
| `doctorReviewerName` | Имя врача-ревьюера. На MVP пусто | нет |
| `days` | Массив дней | да |

### День

```jsonc
{
  "dayNumber": 1,                   // с 1, без пропусков
  "isRescanCheckpoint": true,       // день пересъёмки
  "theory": "## Заголовок\n\nТекст в Markdown…",
  "tasks": [
    { "title": "Короткое действие", "description": "Необязательное пояснение" }
  ]
}
```

| Поле | Что это |
|---|---|
| `dayNumber` | Номер дня, с 1, подряд без дыр |
| `theory` | Теория дня в **Markdown**: заголовки `##`, списки, `**жирный**` |
| `isRescanCheckpoint` | День, когда просим переснять глаз. По этим дням строится график Hb в прогрессе |
| `tasks` | Задачи дня. Формально может быть пустым, но день без задач — это день без действия |

### Задача

| Поле | Что это |
|---|---|
| `title` | Короткая формулировка действия, до 200 символов |
| `description` | Необязательное пояснение, до 2000 символов |
| `id` | **Не заполнять.** Проставит импортёр при первом импорте |

---

## Чекпоинты: где ставить

Дни с `isRescanCheckpoint: true` — это точки графика гемоглобина в разделе
прогресса. Разумный минимум — **три**: старт, середина, финал.

Для курса на 21 день: дни 1, 11, 21. В примере на 7 дней — 1, 4, 7.

Меньше трёх точек — график не читается. Больше шести на три недели — пересъёмка
начинает раздражать.

---

## Что проверит импортёр

Файл не загрузится, если:

- `durationDays` не совпадает с количеством элементов в `days`;
- `dayNumber` идут не с 1 или с пропусками, или повторяются;
- `slug` не в формате `строчные-буквы-через-дефис`;
- пустой `theory` или пустой `title` у задачи;
- `contentStatus: "Published"` — но курс при этом неполный.

Проверить файл заранее можно любым валидатором JSON Schema, скормив ему
`schemas/course.schema.json`.

---

## Про повторный импорт

Если курс уже идёт у пользователей, **менять `id` задач нельзя**: на них
ссылается прогресс в `CourseEnrollment`, и смена id обнулит галочки у всех, кто
на курсе. Импортёр при повторной загрузке сохраняет существующие id, сопоставляя
задачи по дню и порядку внутри дня.

Отсюда практическое следствие: **править формулировки — можно, вставлять и
переставлять задачи в уже опубликованном курсе — нежелательно.** Если нужно
серьёзно переработать курс, который уже идёт, лучше завести новый `slug`.

---

## Чего в схеме сознательно нет

- **Цен и платных дней.** Платёжный слой удалён из проекта 22.09.2026, курсы
  бесплатны безусловно.
- **Картинок и видео.** На MVP только текст. Если материал просит иллюстрации —
  скажите, добавим поле.
- **Переводов.** Мультиязычность вне MVP; один курс — один язык.
